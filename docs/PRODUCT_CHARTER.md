## 1. 使命

> **BigPRC 的目标不是收录互联网，而是帮助用户更快做出正确选择。**

这意味着：
- 筛选比收集更重要——不是无限收录，而是精选
- 判断比信息更重要——用户需要的是观点，不是列表
- 决策比浏览更重要——每个页面都应该帮助用户回答"我该不该用这个？"

## 2. 品牌定位

### BigPRC 是谁

> **中文世界最好用的数字资源策展库。**
>
> Hero Slogan：**发现好工具**
> 副标题：精选值得长期使用的数字工具与学习资源

BigPRC 的核心价值是 **策展（Curation）**——不是收集得最多，而是筛得最好。
用户来 BigPRC 不是因为这里什么都有，而是因为这里**有判断、有观点、有选择标准**。

### BigPRC 不是谁

| 不是 | 原因 |
|------|------|
| ❌ 资源下载站 | 不强调下载，不强调"免费"，不强调数量 |
| ❌ 导航站 | 不是链接集合，每个条目都有编辑判断 |
| ❌ 搜索引擎 | 搜索是辅助功能，不是首页唯一入口 |
| ❌ Product Hunt | PH 追踪新品，BigPRC 策展长期价值的数字资源（Evergreen） |
| ❌ 博客 | 不以文章为主体，但可以为工具写"为什么推荐" |

### 一句话区分

> Product Hunt 回答：**What's new?**
> BigPRC 回答：**What's worth using?**

### 对标参考

| 网站 | 借鉴什么 | 不借鉴什么 |
|------|---------|-----------|
| Product Hunt | 首页浏览循环、Collections 组织方式 | 时间流、新品驱动 |
| Wirecutter | "为什么推荐"的逻辑、决策帮助 | 长篇评测 |
| App Store | 编辑精选卡片、专题推荐 | 付费下载模式 |
| GitHub Explore | 合集、Topic 组织 | 代码仓库模型 |

## 3. 产品原则

作为以后所有设计、开发、内容决策的判断标准。

### 原则 1：策展优先于收录

> 不是收得最多，而是筛得最好。

- 决定"不放什么"比"放什么"更重要
- 每个资源被收录都应该有一个理由
- 数量是辅助信息，不应该是 Hero 核心

### 原则 2：浏览优先于搜索

> 让用户即使没有明确目标，也能不断发现值得看的内容。

- 首页必须形成"浏览循环"——永远有下一屏
- 搜索是辅助工具，放在首页但不作为唯一入口
- 合集（Collections）是核心浏览方式

### 原则 3：内容优先于设计

> 视觉服务于内容，不是内容藏起来。

- 首页首屏必须有 Google 可索引的真实内容
- 不做纯 JS 渲染的空壳页面
- 设计追求的是"读起来舒服"，不是"看起来炫"

### 原则 4：AI 负责生产，编辑负责判断

> AI 做作业，编辑做决策。

- **AI 的职责**：总结、分类、描述、推荐候选、标签生成
- **编辑的职责**：选择、修改、删除、是否推荐、一句点评
- **工程铁律**：流水线永远不因为编辑缺席而阻塞
  - 编辑在线 → 审核后发布
  - 编辑不在 → AI 草稿正常发布，标记"AI 辅助"
  - 编辑随时可以替换为人工版本

### 原则 5：品牌优先于功能

> 每增加一个模块，都要回答一个问题：
> 它是在强化「BigPRC 是谁」，还是在增加一个功能？

- 功能可以少，品牌不能模糊
- 不做"资源站"的功能（如批量下载、积分体系）
- 做"策展平台"的功能（如编辑点评、合集、推荐理由）

### 原则 6：内容真实，观点诚实

> 真正的推荐包含边界，而不是一味赞美。

- 每个详情页回答四个问题：
  1. 这是什么
  2. 适合谁
  3. 为什么推荐
  4. **什么时候不用它**（这一点区分 AI 生成和人类判断）
- 边界信息（局限性、替代方案）比赞美更有信任价值

## 4. 首页信息架构

### 渲染策略：混合 SSR

| 区块 | 渲染方式 | 原因 |
|------|---------|------|
| Hero + Slogan | SSR | 首屏可见，品牌传达 |
| 今日推荐（Editor's Pick） | SSR | Google 可索引，建立编辑权威 |
| 热门工具（6 卡片） | SSR | 内容实体，SEO 核心 |
| 专题入口（4-6 合集） | SSR | 长尾关键词入口 |
| 最新更新 | JS 异步 | 非首屏，减少 HTML 体积 |
| 猜你喜欢 | JS 异步 | 个性化，需用户数据 |
| 更多资源 / 排行榜 | JS 异步 | 辅助浏览 |

### 浏览循环

```
Hero
  ↓
今日推荐（1-2 卡片，编辑精选）
  ↓
热门工具（6 卡片网格）
  ↓
专题入口（4-6 合集，大色块卡片）
  ↓
最新更新（4 卡片）
  ↓
猜你喜欢（4 卡片，异步加载）
  ↓
分类浏览（折叠式入口）
  ↓
Footer
```

### 首屏内容原则

- Hero 区：Slogan + 搜索框（搜索框缩小比例，不再是唯一元素）
- 首屏至少展示 6 条资源实体（让 Google 确认"这是一个内容网站"）
- 每个 SSR 卡片包含：标题 + 分类 + 一句话描述 + 链接

## 5. 详情页信息架构

### 内容顺序（面向决策）

```
1. 资源标题
2. 一句话定位（是什么）
3. 适合谁 / 不适合谁
4. 为什么推荐（编辑点评）
5. 什么时候不用它（边界说明）
6. 类似工具 / 替代方案
7. 基本信息（大小、平台、版本）
8. 访问官网（CTA 放在最后）
```

### 设计原则

- CTA 不放第一屏——先建立信任，再引导行动
- "不适合谁"和"什么时候不用"是建立信任的核心模块
- 类似工具推荐形成内链蜘蛛网，提升整站浏览深度

## 6. 合集（Collections）

### 定位

> Collections 不是一种页面类型，而是整个网站的信息组织方式。

### 数据结构

```
resource ←→ resource_collection ←→ collection
```

一个资源可以属于多个合集。合集不同于分类：
- **分类** 是数据库属性（AI / 开发 / 设计）
- **合集** 是编辑视角（Mac 必装 / AI 编程工具 / 自媒体工具箱）

### 合集即入口

- 首页专题推荐 → 合集
- 详情页"类似工具" → 同合集的其他资源
- 合集页 → 独立 SEO 着陆页（如 "mac 必装软件 2026"）

## 7. 路线图

### 第一阶段：品牌建立（当前）

| 优先级 | 内容 | 目标 |
|--------|------|------|
| P0 | 首页 SSR 改造（Jinja2 模板化） | 首页有可索引的真实内容 |
| P1 | 品牌定位落地（Slogan + IA 重构） | 用户 3 秒理解 BigPRC 是什么 |
| P2 | 详情页决策化升级 | 提升停留时间和信任感 |
| P3 | SEO 基础设施（Schema、内链、面包屑） | 放大已有内容价值 |
| P4 | 中转页优化 | 减少跳转流失 |
| P5 | 社交分享 | 增强传播效率 |

### 第二阶段：合集与编辑体系

- Collections 数据表 + 合集页面模板
- 编辑工作流（标记、筛选、一句话点评）
- AI 推荐理由候选生成

### 第三阶段至第六阶段（预留）

- 教程与使用经验
- Newsletter
- 社区功能

> 第三阶段及以后的内容不作为当前开发目标，但信息架构从第一天起预留扩展空间。
